# 人物 AI 测试结果（2026-11-08）

模型：Qwen 3.5 2B q4_k_m（开发期用，没有微调），RTX 4050。全部用 `scenes/tests/model_test.tscn` 跑，命令见文末。

## 1. 人设变生动后判断变差，改成"先判断再说话"

`tests/model_test/lines.csv` 的 50 句，15 岁、第 3 周，每个设置跑 2 个种子取平均。

| 提示词 | intent 选对 | 态度选对 | 每句（中位数） |
| --- | --- | --- | --- |
| 原来的提示词（第 1 步） | 28 | 36 | 0.94 秒 |
| 完整角色卡 + 状态卡，边演边判断 | 22 | 22.5 | 1.2 秒 |
| 去掉示例对话 | 20 | 27 | 1.2 秒 |
| 只留一句身份介绍 | 29 | 33 | 1.2 秒 |
| 精简角色卡 | 25.5 | 30 | 1.1 秒 |
| **先用短提示单独判断，再带完整角色卡说话（现在用的）** | **38.5** | **37** | **1.5 秒**（判断约 0.33 秒） |

结论：小模型一边演角色一边判断，性格写得越生动越容易判错（把鼓励判成普通、把普通判成敷衍）。
分成两步后判断比原来还准，角色卡也能写完整。代价是每句多约 0.3～0.5 秒。
开关是 `data/balance.csv` 的 `model_separate_judge`：微调后如果一步就判断得准，可以改成 0 省掉这一步。

注意：判断和说话必须共用一次加载的模型。测试里分别加载两次时显存不够，判断一句要 3.5 秒。

## 2. 每次带几条记忆（策划要求实测 3 / 5 / 8）

`tests/model_test/memory_seed.csv` 放 15 条事件记忆（8 岁和 15 岁的都有）+ 2 条核心记忆（喜欢的颜色、约定），
`memory_lines.csv` 问 12 个要靠记忆才答得对的问题（"小芽叫什么""ARK-01 哪里坏了"），看回复里有没有说出关键词。每个设置 3 个种子。

| 带几条 | 答对（3 次） | 每句（中位数） |
| --- | --- | --- |
| 0（只有核心记忆） | 2、1、2 | 1.21 秒 |
| 3 | 7、7、4 | 1.22 秒 |
| 5 | 8、8、5 | 1.24 秒 |
| 8 | 8、8、6 | 1.27 秒 |
| 5（相关度改进后，现在用的） | 8、8、6 | 1.24 秒 |

结论：定 **5 条**。比 3 条多记得一些，速度几乎不变；8 条和 5 条一样，因为一句话相关的记忆很少超过 5 条（不相关的不带）。
没带事件记忆时她基本答不上来，说明记忆确实起作用。

还会出的问题：
- 记忆带进去了，她有时还是不提（比如问 ARK-01 哪里坏了，她说"我去检查"）。
- 偶尔把两条记忆混在一起（把"苗被挖走"说成"豆豆没被挖走"）。
- 这两点要靠微调数据改善：训练数据里要有"状态卡带了记忆 → 回答里用上"的样本。

## 怎么重新跑

```
Godot_v4.6.1-stable_win64_console.exe --headless --path . res://scenes/tests/model_test.tscn -- --model=模型路径 --auto --judge --seed=1 --out=结果.json
Godot_v4.6.1-stable_win64_console.exe --headless --path . res://scenes/tests/model_test.tscn -- --model=模型路径 --judge --memory=5 --seed=1 --out=结果.json
```

去掉 `--judge` 就是"边演边判断"的旧做法。`--memory=` 后面是带几条记忆。
