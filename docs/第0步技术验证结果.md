# 第 0 步技术验证结果（2026-11-07）

测试电脑：i9-13900H、RTX 4050 6 GB 显存、16 GB 内存。Godot 4.6.1，NobodyWho 13.0.0。
模型：Qwen 2.5 3B（q4_k_m，1.8 GB），没有微调，人设和判断规则都是临时写的。
测试：`tests/model_test/lines.csv` 的 30 句话，每句前清空对话历史。

| 项目 | 有显卡 | 只用 CPU（测 15 句） |
| --- | --- | --- |
| 每句回复（中位数） | 0.94 秒 | 3.0 秒 |
| 最慢一句 | 1.5 秒 | 3.4 秒 |
| 第一句（含预热） | 2.2 秒 | 5.4 秒 |
| 加载模型 | 5～8 秒 | 2.5 秒 |
| 合法 JSON | 30/30 | 15/15 |
| intent 选对 | 22/30 | 12/15 |

只用 CPU 的数字来自这台电脑的高性能 CPU，不代表普通电脑。

## 判断准确度

- `intent`：错的 8 句主要在"撤回来""向你求助""只是聊天"，常被判成 `continue`。
- `player_attitude`：只对 10/30，大多数都判成了 `encourage`，4 句限制的话有 3 句判成鼓励。这个标签会改数值，上线前必须改善。
- 这些"正确答案"是写测试时人工定的，有的句子可以有不同理解。

## 显存

测试时显存峰值 5.4 GB（共 6.1 GB），其中约 2.7 GB 是其他程序已占用的，模型约占 2.7 GB。
还没有和 3D 画面同时跑过，第 2 步有场景后要复测。

## 打包大小

Windows 版：游戏程序和插件 237 MB + 模型 1.8 GB，合计约 2.1 GB。目前项目还没有正式画面，美术和声音另算。

## 还没验证

- 真正没有独立显卡的电脑（需要另一台电脑）。
- 模型和 3D 画面同时运行。
- 打包后的游戏实际运行（要等第 1 步有主场景）。

## 踩过的坑

1. 格式表要把文件原文传给插件。Godot 解析 JSON 会把 3 变成 3.0，插件会报错。
2. 只限制格式还不够：模型可能在字段之间无限输出空格，一句话卡 16 秒，最后 JSON 也不完整。`model_output_schema.json` 里关掉了多余空格（`x-guidance`），并限制了文字长度，改完后 30 句全部合法。
3. 插件程序文件 143 MB，超过 GitHub 单文件上限，没进仓库，安装方法见 `addons/README.md`。

## 怎么重新跑

在项目文件夹里运行（把模型路径换成实际路径）：

```
Godot_v4.6.1-stable_win64_console.exe --path . res://scenes/tests/model_test.tscn -- --model=模型路径
```

这是手动聊天。加 `--auto --out=结果文件.json` 是自动跑分，再加 `--cpu` 只用 CPU。


## 基底模型对比：Qwen 3.5 2B 和 Qwen 2.5 3B（2026-11-07）

用同样的 30 句和提示词。两者都没有微调。同一模型连跑 3 次结果完全相同，所以这是一份固定的样本，不是 3 份独立样本。

| 项目 | Qwen 3.5 2B | Qwen 2.5 3B |
| --- | --- | --- |
| 进游戏的模型文件 | 1.19 GB（Ollama 下载 1.9 GB，含用不上的看图部分 0.63 GB） | 1.80 GB |
| 显存增量（峰值减开始前） | 约 1.8 GB | 约 2.7 GB |
| 每句回复（中位数 / 最慢，有显卡） | 0.79 / 1.35 秒 | 0.94 / 1.54 秒 |
| 每句回复（中位数 / 最慢，只用 CPU） | 2.6 / 3.1 秒 | 3.0 / 3.4 秒 |
| 合法 JSON | 30/30 | 30/30 |
| intent 选对 | 13/30 | 22/30 |
| 态度选对 | 23/30 | 10/30 |
| 选项里有乱码或格式碎片 | 4/30 | 2/30 |
| 说话感觉 | 短、有情绪，偶尔答非所问 | 客气、像助手，多为"好的，我会…" |

每个模型的显存只测了一次，开始前其他程序占用的显存也不同（2B 约 3.1 GB，3B 约 2.7 GB），只能当大致参考。

结论：2B 更省资源，说话更像人；3B 判断 intent 更准。提示词还没调过，两边都有提升空间，基底在微调前定死。Qwen 3.5 的微调流程还没实际验证过。
## 调提示词后复测（2026-11-07，第 1 步结束时）

提示词加了判断规则和例子，输出顺序改成先判断再说话（用 `text/prompts/girl_zh.txt`）。多加了 20 句调提示词时没看过的新句子。都没有微调。

| 项目（共 50 句） | Qwen 3.5 2B | Qwen 2.5 3B |
| --- | --- | --- |
| intent 选对 | 23/50 | 40/50 |
| 态度选对 | 37/50 | 22/50 |
| 选项有乱码（程序会换成后备选项） | 9/50 | 1/50 |
| 每句回复（中位数，有显卡） | 0.88 秒 | 0.79 秒 |

结论：调提示词基本没改变差距。前 30 句和上次比，2B 的 intent 从 13 变成 11，3B 从 22 变成 25，都在误差范围内。两个模型各错各的：2B 的 intent 大多选 none 或 clear，3B 的态度大多判成 encourage。靠提示词解决不了，要看微调的效果。

## 基底定死之前要做的

用少量数据各做一次小规模试训，比较训完后的判断准确度，再定基底。这也能确认 Qwen 3.5 能不能走通微调流程。

## 提示词加完整例子后（2026-11-07，试玩反馈后）

试玩发现选项写成了她说的话。提示词写清楚"选项是玩家说的"，加一个完整的 JSON 例子，并告诉模型这周上了什么课。

| 项目（共 50 句） | Qwen 3.5 2B | Qwen 2.5 3B |
| --- | --- | --- |
| intent 选对 | 32/50（上次 23） | 25/50（上次 40） |
| 态度选对 | 40/50（上次 37） | 26/50（上次 22） |
| 含"我"开头选项的句子 | 6/50 | 12/50 |

3B 经常把例子里的选项原样抄下来，2B 没有。这是第一次出现一个模型两项都领先，但两次结果差距很大，说明结果对提示词写法很敏感，还要靠试训确认。

选项说话人仍未完全修好：2B 有些选项还带着她的口吻。训练数据要专门覆盖"选项是玩家说的话"。

## 加入随机后（2026-11-07，修复重复回答）

之前回答每次都一样，同样的话得到同样的回答，所以容易重复。现在每次开游戏换随机种子，加重复惩罚（参数在 `data/balance.csv`），提示词的例子换成和课程无关的内容。每个模型跑 3 个不同种子，下面是 50 句的平均值。

| 项目 | Qwen 3.5 2B | Qwen 2.5 3B |
| --- | --- | --- |
| intent 选对 | 29 | 32 |
| 态度选对 | 36 | 26 |
| 选项有乱码（程序会换成后备选项） | 3 | 0 |
| 抄例子的句子 | 0 | 不到 1 |
| 每句回复（中位数，有显卡） | 约 0.86 秒 | 约 0.84 秒 |

这是目前最可信的一组：样本多了种子，没有抄例子的干扰。前面几组因为回答固定，差距被放大了。

一次测试卡住超过 8 分钟（第一次）的原因仍未确定。另一次卡住发生在最后一轮中途改人设时，已改掉。第三次是脚本有错导致测试不退出，和模型无关。
